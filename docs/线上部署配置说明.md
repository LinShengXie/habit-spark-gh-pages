# Habit Spark 线上部署配置说明

前端：GitHub Pages（如 `https://linshengxie.github.io/habit-spark-gh-pages/`）  
后端：Railway（如 `https://note-production-e836.up.railway.app`）

---

## 1. 你遇到的报错对应关系

| 报错 | 含义 | 处理 |
|------|------|------|
| `login:1 Failed to load resource: 404` | 直接访问 `/login` 时，GitHub Pages 没有该路径文件，返回 404 | 见下文「前端：GitHub Pages 直链 404」 |
| `CORS policy: No 'Access-Control-Allow-Origin' header` | 后端未对前端域名放行跨域 | 见「后端：CORS」 |
| `POST .../auth/register net::ERR_FAILED 500` | 后端接口 500，常见为环境变量或数据库问题 | 见「后端：500 与环境变量」 |

---

## 2. 前端：GitHub Pages 直链 404

- 原因：SPA 只有 `index.html`，直接打开 `/habit-spark-gh-pages/login` 时，GitHub 会按路径找文件，没有则 404。
- 处理：构建时已增加 **复制 `index.html` 为 `404.html`**（见 `vite.config.ts`），部署后任意路径都会落到同一份 SPA，由前端路由处理。
- 操作：重新执行一次 **build 并推送到 GitHub**，确保 `dist/`（或 GitHub Actions 的产出）里包含 **404.html**，再部署到 Pages。

---

## 3. 后端（Railway）：CORS

- 代码里已对 `https://linshengxie.github.io` 做了 CORS 放行（`main.py` 的 `allow_origins`）。
- 若仍出现 CORS 报错，通常是因为：
  1. **Railway 上的不是最新代码**：没有包含上述 CORS 配置。  
     → 把当前 habit-api 代码推送到 Railway 使用的仓库/分支，触发重新部署。
  2. **先报了 500**：部分环境下 500 响应未带 CORS 头，浏览器会先报 CORS。  
     → 先按下一节修好 500，再试。

---

## 4. 后端（Railway）：500 与环境变量

`/auth/register` 返回 500 多为下面几类原因，请在 Railway 里逐项检查：

| 项目 | 说明 |
|------|------|
| **DATABASE_URL** | 必须配置且可连。Neon 的 PostgreSQL 连接串；若平台给的是 `postgres://`，后端已自动替换为 `postgresql://`。 |
| **SECRET_KEY** | 必须配置。JWT 签名用，生产环境用随机长字符串（建议 32 位以上），可用 `python -c "import secrets; print(secrets.token_hex(32))"` 生成。 |
| **R2 相关**（可选） | 若使用打卡配图/头像上传，需配置 `R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`R2_BUCKET_NAME`、`R2_PUBLIC_URL`。 |

建议：在 Railway 该服务的 **Variables** 里确认 **DATABASE_URL**、**SECRET_KEY** 已填且无误；若出现 500，可在 **Deployments → View logs** 查看具体报错。

## 5. 问题记录（线上排错）

### passlib 与 bcrypt 在 Python 3.13 下不兼容（已修复）

- **现象**：Railway 部署后 `POST /auth/register` 返回 500，日志出现 `AttributeError: module 'bcrypt' has no attribute '__about__'` 及 `ValueError: password cannot be longer than 72 bytes`。
- **原因**：passlib 依赖 bcrypt 的 `__about__` 取版本号，bcrypt 4.1+ 已移除该属性；在 Python 3.13 环境下触发不兼容。
- **修复**：鉴权改为直接使用 `bcrypt` 库做密码哈希与校验，移除对 passlib 的依赖（见 `habit-api/auth.py`、`requirements.txt`）。哈希格式仍为标准 bcrypt，已有用户密码可照常校验。

## 6. 前端：生产环境 API 地址

- 构建时通过 **VITE_API_BASE_URL** 决定请求的后端地址。
- 仓库里 `.env.production` 已写为：  
  `VITE_API_BASE_URL=https://note-production-e836.up.railway.app`
- 若你的 Railway 地址变了，改 `.env.production` 后重新 build 并部署。
